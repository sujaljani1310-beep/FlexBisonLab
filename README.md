# FlexBisonLab

A hands-on learning project exploring **lexical analysis**, **parsing**, grammar rules, and expression evaluation with **Flex**, **GNU Bison**, and **C**. The long-term goal is to learn compiler fundamentals by gradually developing a tiny programming language.

## Current status — Version 2: Arithmetic expression evaluator

The current program recognizes and evaluates **one integer arithmetic expression per run**.

| Feature | Example | Result |
| --- | --- | --- |
| Addition | `10 + 5` | `15` |
| Subtraction | `20 - 5` | `15` |
| Multiplication | `10 * 5` | `50` |
| Division (integer) | `7 / 2` | `3` |
| Operator precedence | `10 + 5 * 2` | `20` |
| Parentheses | `(10 + 5) * 2` | `30` |
| Left associativity | `20 - 5 - 3` | `12` |
| Division by zero | `10 / 0` | Reports an error |

Division truncates toward zero because the parser uses C's `int` arithmetic. Division by zero is checked before attempting division, and parsing is aborted.

### Version history

- **Version 1 — Addition calculator:** Recognized integers and `+`, then evaluated simple sums.
- **Version 2 — Arithmetic evaluator (current):** Added `-`, `*`, `/`, precedence, left associativity, parentheses, and division-by-zero handling.

This is an educational expression evaluator, **not yet a full compiler**.

## How Flex and Bison work together

```text
Input: (10 + 5) * 2
          |
          v
Flex scanner (lexer.l)
   '(', NUMBER(10), '+', NUMBER(5), ')', '*', NUMBER(2)
          |
          v
Bison parser (parser.y)
   Validates the expression using grammar rules
   and evaluates it using semantic actions
          |
          v
Result: 30
```

### `lexer.l` — Lexical analysis

Flex recognizes sequences of characters as tokens.

- `[0-9]+` matches one or more digits.
- `yytext` contains the text that matched, such as `"20"`.
- `atoi(yytext)` converts digit text into an integer.
- `yylval` passes that integer value to Bison.
- `return NUMBER;` passes the token *type* to Bison.
- Rules such as `"+" { return '+'; }` return literal operator tokens.

The lexer also recognizes `-`, `*`, `/`, `(`, and `)`, ignores whitespace, and passes otherwise unrecognized characters to the parser.

### `parser.y` — Syntax analysis and evaluation

Bison checks whether tokens follow the grammar and applies C semantic actions. Examples:

```bison
expression '+' expression   { $$ = $1 + $3; }
expression '*' expression   { $$ = $1 * $3; }
'(' expression ')'          { $$ = $2; }
```

- `$1`, `$2`, `$3` refer to the values of grammar symbols on the rule's right-hand side.
- `$$` is the value assigned to the left-hand-side grammar symbol.
- Parentheses keep the value of the inner expression: `$$ = $2;`.
- `%left '+' '-'` gives addition and subtraction equal precedence and left associativity.
- `%left '*' '/'` (declared afterward) gives multiplication and division higher precedence.
- The division rule checks whether the denominator (`$3`) is zero and calls `YYABORT` if so.

The program's `main()` calls `yyparse()` (generated by Bison), which calls `yylex()` (generated by Flex) whenever it needs another token. `yyparse()` returns a parsing status, **not** the arithmetic result.

## Requirements

- Flex
- GNU Bison
- A C compiler, such as Clang or GCC

On macOS with Homebrew:

```bash
brew install flex bison
export PATH="$(brew --prefix flex)/bin:$(brew --prefix bison)/bin:$PATH"
```

## Build

From the repository folder:

```bash
bison -d parser.y
flex lexer.l
clang parser.tab.c lex.yy.c -o calculator
```

- `bison -d` generates `parser.tab.c` and `parser.tab.h`.
- `flex` generates `lex.yy.c`.
- `clang` compiles the two generated C files into the `calculator` executable.

Generated source files and executables are excluded from version control.

## Run and test

The easiest way to run an expression is with `echo`:

```bash
echo "10*5+2" | ./calculator
echo "(10+5)*2" | ./calculator
echo "20-5*2" | ./calculator
echo "20/2*5" | ./calculator
echo "7/2" | ./calculator
echo "10/0" | ./calculator
```

The first five should produce `52`, `30`, `10`, `50`, and `3` respectively. The last reports division by zero.

For example:

```text
Enter an expression: Result: 30
```

You can also launch it interactively:

```bash
./calculator
```

Enter an expression and then signal **EOF** with **Ctrl+D** on macOS/Linux. Newlines are currently ignored by the lexer, so pressing Enter alone does not finish an expression.

### Current limitations

- One expression per process, rather than an interactive multi-line REPL
- Integer arithmetic only; no floating-point numbers
- No variable assignments, print statements, or user-defined functions
- No unary minus rule (for example, `-5` is not supported yet)
- The program does not check integer overflow or out-of-range numeric literals
- Division by zero is currently displayed with the generic prefix `Syntax error:` because `yyerror()` is reused for arithmetic errors

## Next milestone — Stage 3: Tiny programming language

Rather than adding more calculator-only features, the next goal is to introduce **identifiers, variables, assignments, statements, and a symbol table**.

Target syntax (not implemented yet):

```text
x = 10;
y = 20;
print(x + y);
```

Target output:

```text
30
```

After that, the project can grow toward:

1. **Abstract syntax trees (ASTs)** that represent code rather than immediately evaluating it
2. **Conditions, loops, and functions** using richer grammar rules
3. **Semantic analysis** to detect undefined identifiers and other code errors
4. **A tiny interpreter or code generator** built on top of the AST

## Learning goals

- Understand how tokenization differs from parsing
- Practice Flex regular expressions and scanner actions
- Learn Bison grammar productions, semantic values, precedence, and associativity
- Understand generated C code and the interaction between `yyparse()` and `yylex()`
- Progress from an arithmetic evaluator to a small language front end

This repository is an ongoing learning lab, not a production-ready compiler.
